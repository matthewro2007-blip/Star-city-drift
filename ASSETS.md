(`tools/gen_matthew_v2.py`: same proportions, head-to-body ratio, 2px silhouette outline, 4-step cel

opaque pixel) on row 189**. Run `python3 tools/check_sprites.py` to verify every contract + rebuild previews.

(the old procedural tan-skin drawing is only used if `matthew_sheet.png` itself fails to load).

## Animation manifest (`assets/sprites/anims.json`, enemies: `assets/sprites/anims_enemies.json`)
Extended animations live in NEW strips only; the 8-frame sheets above are untouched.
Strip: `assets/sprites/<key>_anim.png`, ONE row of 144×192 frames (x = index·144, y = 0), facing right,
transparent, lowest opaque pixel on row 189 except frames marked `grounded:false` (airborne) — `lying:true`
frames also sit on row 189. Both manifests use the same schema and are merged by `loadSprites()`
(`anims_enemies.json` is optional; missing = silently skipped):
```json
{
  "version": 1, "frameW": 144, "frameH": 192, "feetRow": 189,
  "characters": {
    "<key>": {
      "file": "assets/sprites/<key>_anim.png",
      "states": {
        "<state>": {
          "file": "assets/sprites/<key>_anim.png",
          "frames": [0, 1, 2],            // strip indices, in play order
          "fps": 12, "loop": true,
          "grounded": [true, true, true], // false = airborne frame (feet above row 189)
          "lying":    [false, false, false],
          "active":   [false, true, false],                 // attack active frames
          "hitbox":   [null, {"x": 90, "y": 60, "w": 28, "h": 24}, null]   // frame-local px, null if none
        }
      }
    }
  }
}
```
**Wide cells (never clip) — one schema for anims.json and anims_enemies.json:** every state carries
`fw`, `fh`, `anchorX` and per-frame `sx`/`sw`/`sy`/`sh` arrays. States that fit 144×192 (anchorX 72) live in
`<key>_anim.png`; states whose poses would touch a frame edge (lying, lunges, jump kick, FX) live in
`<key>_anim_wide.png` at 240×192 (anchorX 120), and the character entry carries `wideFile`. A state's `file`
says which; frame indices count within that state's own file. Feet sit on row `sh-3` (189).
`aliasOf: [stateA, stateB, ...]` marks an alias (snatcher `ko` = caught+knockdown_fall+knockdown_ground,
silas_boss `ko` = defeat); if the alias has its own frames they are used, otherwise JS concatenates the named states.
`getAnimFrame` returns `anchorX` and `feetRow`: draw at `(actorX - anchorX, groundY - feetRow)`
(mirror about anchorX when facing left). Strips/wide files are all preloaded by `loadSprites()`.

Keys: `matthew_<outfit>` (polo, photo, hoodie, jacket, street, varsity, mechanic, diner, gold, webslinger, beacon, ironclad, silas; their `idle_signature` / `combo3` / `special` are per-outfit **kit** states from `tools/gen_kits.py`, see "Outfit kits" below — the old shared versions still sit unreferenced in `<key>_anim(_wide).png`),
cast `dee hank priya cam june silas tessa coach wren`, prequel cast `lou gus ivy pip` (1.5.2); enemies (Jack) `silas_boss`, `thug_<colour>`, `snatcher`.
Shared rig (Python, run from repo root): `sys.path.insert(0, "tools"); import gen_matthew_v2 as g; import gen_cast as gc`
— `g.pose(**kw)`, `g.render_figure(cv, P)`, `g.finish(cv)`, `g.Canvas(144, 192, xf)`, `g.POSES`, `g.set_outfit(id)`,
`gc.setup(gc.THUGS[key] | gc.SILAS | gc.SNATCHER)` (sets skin/head/outfit), `gc.draw_prop_at(cv, kind, pt, ang, k)`
(kinds incl. `pipe`, `purse`). Reference renderer + snapping/hitbox code: `tools/gen_anims.py` (`render_spec`, `job`).
JS: `getAnimFrame(charKey, state, tMs, outfit?)` → `{img, sx, sy, sw, sh, anchorX, feetRow, done, active, hitbox, grounded, lying, index}` or `null` (unknown key/state). `listAnims(charKey, outfit?)` → state names; `ANIM_STATES` lists names per group. Hitboxes are cell-local px. Harness: `tools/anim_check.html` plays every state.
Keys are forgiving: case/camelCase/dash-insensitive (`Dee`, `coachRay`, `coach_ray`, `thug-Purple`), name aliases (`Coach Ray`, `silas_npc`, `boss`), `matthew_<outfit>` or `matthew` + outfit as a string or `{id}`. A Matthew outfit missing a state falls back to polo for that state only; `null` only for truly unknown states. `hasAnims(charKey, outfit?)` is true only when that exact key/outfit has its own strips. Manifests are fetched `no-cache` and strips get `?v=<manifest hash>`, so regenerated art is never served stale.

use `sh`/`feetRow` from `getAnimFrame`, never a hard-coded 192. Gold "Encore" has two separate hits (frames 3 and 5, frame 4 inactive):
reset hit-once per active run. Hitboxes are cell-local px (wide cells include the 48 px left pad), computed from the weapon/FX geometry.

## Collectibles (`assets/sprites/collectibles.png` + `collectibles.json`, from `tools/gen_collectibles.py`)
One row per item (rows 0–18 in js/missions.js order, then appended rows), 6 columns of 48×48, transparent, hard alpha (0/255), item ~32–44 px,
bottom on row ~44, same ink/cel/gold-rim style as the rig. Frames 0–5 = idle loop: bob baked in (0,−1,−2,−1,0,+1 px) and a
glint sweep + sparkle on frames 2–3; 8 fps. JSON: `{ "_meta": {...}, "<id>": {row, frames:6, fw:48, fh:48, fps:8, name, names[]} }`.
Ids (21 rows): glasses, bottle, hoodie, jacket (Rail Yard Jacket), street (Skate Fit), notebook, photo, flyer, token, bookmark, wax,
webmask, coveralls, ticket, pin, apron, varsity, lantern, beaconring, + appended row 19 `ironclad` ("Hell's Nightmare" v2 helmet: green, gold visor, grey jaw; aliases `ironcrate` / "Hell's Nightmare Armor Crate", so the game's crate id resolves to it), + appended row 20 `silas` ("Boone's Overcoat": flat-laid navy coat, crimson tie, pocket square; names also "Silas Outfit", "Silas Coat", "Iron Handshake"; not referenced by js/missions.js yet). New items are only ever APPENDED. Outfit items use their outfit sheet colours.
JS: `getCollectibleSprite(idOrName, tMs = 0)` → `{img, sx, sy, sw, sh, anchorX: 24, anchorY: 47, id, name}` or `null`;
matches id or name, case-insensitive, parentheticals ignored (`"Web-Slinger Mask (top of the half-pipe)"` → `webmask`).
`drawCollectible(ctx, x, y, name, pulse)` (signature unchanged) draws the item sprite when loaded, else the old yellow dot.
Loaded in `loadSprites()` with `no-cache` + `?v=<json hash>`.

Outfit sheets and outfit portraits load with `?v=SPRITE_REV` (`js/sprites.js`, currently `1.5.2-wren`; 1.5.2 history: `-cast` → `-bosses` (Jack) → `-wren`); bump it whenever sheets are regenerated. Anim strips and collectibles bust by manifest hash automatically.

## Outfit: `silas` — Silas's Suit + Silas six-move set (1.5.1, `SPRITE_REV '1.5.1-silas-outfit'`)
Matthew in Silas Boone's suit (unlocked by the "Prequel: Silas Boone" DLC). Kit tag `kit: {weapon: "Iron Gauntlet", move: "Iron Handshake"}`;
`kitRev` stays `1.3.1-kits`. The gauntlet is drawn only in the three kit states; base sheet, shared states and the six moves are **gloved fists**.
Files: `matthew_silas.png`, `matthew_silas_anim(_wide).png` (shared 14 states, gen_anims), `matthew_silas_kit(_wide).png`
(idle_signature 6@8 loop, combo3 4@12 [1,2], special 8@12 [0,1,4,5] wide, frame 3 airborne), `matthew_silas_moves.png` (20×144)
+ `matthew_silas_moves_wide.png` (31×240), `portrait_matthew_silas.png`, weapons index 12, collectibles row 20. All cells 192 tall, feet row 189.

Six moves — timing = Jack's playable Silas (`characters.silas_player`) exactly, same state + alias names, so `js/silas_moves.js`
can use the identity map for `matthew_silas` too (frames/fps/active; cell):

| move | states | cell |

| Gentleman's Jab | `jab1` 3/14/[1] lead jab · `jab2` 3/14/[1] low body shot · `jab3` 5/12/[1,2] rising finisher; alias `gentlemans_jab` → jab1 | 144 / 72 |
| Velvet Grip | `velvet_grip_grab` 4/10/[1,2,3] → `velvet_grip_throw` 5/12/[3]; alias `velvet_grip` (9/12/[1,2,3,7]) | 240 / 120 |

Jack's short aliases also exist: `grab`/`whiff` → velvet_grip_grab, `throw` → velvet_grip_throw, `stance` → last_word_stance,
`counter` → last_word_strike, `stare` → cold_stare, `rush` → boss_rush. Alias states carry their own concatenated frames + `aliasOf`
(same structure as silas_player). `ANIM_STATES.matthew_silas` lists these extra names. `counter`/`holdLoop` are extra manifest fields
not returned by `getAnimFrame`.

Regenerate / install: `python3 tools/gen_silas_outfit.py [--out DIR] [--jobs N]` (imports the shared rig from tools/ and registers the outfit,
the `gauntlet`/`shockring` drawers and the kit via `tools/silas_ext.py`; writes only to DIR, default `/workspace/tmp_sprite/silas_outfit_build`),
then `python3 tools/install_silas_outfit.py DIR` (copies the 8 PNGs, sets `characters.matthew_silas` + appends `silas` to `outfits`,
appends/refreshes weapons index 12 and collectibles row 20; append-only, earlier icons/rows asserted pixel-identical; idempotent).
**Caveat:** the generic generators don't know `silas` (it's registered by `silas_ext.py` at import): a full `tools/gen_weapon_icons.py` or
`tools/gen_collectibles.py` rebuild writes 12 icons / 20 rows and `tools/gen_kits.py` (no args) won't rebuild the silas kit; a full `tools/gen_anims.py` run resets the top-level `outfits` list
(drops `silas`, keeps `characters.matthew_silas`) — re-run `install_silas_outfit.py` after any of those. `tools/check_kits.py` expects 13 weapons incl. silas.
